## Project Overview

BackingTracks is a music streaming platform with audio upload and playback capabilities. It supports both direct file uploads and YouTube audio downloads via yt-dlp, converting all audio to Opus format for efficient streaming.

## Architecture

**Stack:**
- Backend API: Symfony 7.4 (PHP 8.2)
- Frontend: Nuxt 4 (SSR disabled, SPA mode)
- Database: MariaDB 10.11
- Web Server: Nginx
- Container Orchestration: Docker Compose
- Package Manager: Composer (API), npm (Frontend)

**Authentication:**
- JWT-based authentication via LexikJWTAuthenticationBundle
- Refresh token support via gesdinet/jwt-refresh-token-bundle
- Public endpoints: `/api/register`, `/api/login`, `/api/token/refresh`
- Protected endpoints: all other `/api/*` routes require `IS_AUTHENTICATED_FULLY`

**Audio Processing:**
- All audio converted to Opus format (64 kbps)
- FFmpeg for file uploads
- yt-dlp for YouTube downloads
- Files stored in `/public/uploads/music/`
- Images stored in `/public/uploads/images/`

## Development Setup

### Initial Setup
```bash
# Copy environment file
cp .env.example .env

# Generate secrets (if needed)
openssl rand -hex 32  # For APP_SECRET and JWT_PASSPHRASE

# Start all services (production mode)
docker-compose up -d

# Start with hot reload (development mode)
docker-compose -f docker-compose.yml -f docker-compose.dev.yml up
```

### API Commands (run inside API container or locally)
```bash
# Access API container
docker exec -it api sh

# Run database migrations
php bin/console doctrine:migrations:migrate

# Create a new migration
php bin/console make:migration

# Generate JWT keypair (auto-generated by entrypoint.sh)
php bin/console lexik:jwt:generate-keypair

# Clear cache

# Load fixtures (dev only)
php bin/console doctrine:fixtures:load

# Create entity/controller
php bin/console make:entity
php bin/console make:controller

# Debug routes
php bin/console debug:router
```

## Key Directories and Patterns

### Backend (API)
- `src/Controller/` - API endpoints organized by resource
  - `Admin/` - Admin-specific controllers for CRUD operations
  - Controllers use Symfony Route attributes
- `src/Entity/` - Doctrine ORM entities
  - `User`, `Artiste`, `Album`, `Musique`, `RefreshToken`
- `src/Repository/` - Doctrine repositories for database queries
- `src/Service/` - Business logic services
  - `AudioUploader` - Handles audio uploads and YouTube downloads
  - `ImageUploader` - Handles image uploads
- `config/packages/` - Bundle configuration
  - `security.yaml` - JWT authentication config
  - `nelmio_cors.yaml` - CORS configuration
  - `lexik_jwt_authentication.yaml` - JWT settings
- `migrations/` - Database migrations

### Frontend (Nuxt)
- `app/pages/` - File-based routing
  - `auth/` - Login and registration pages
  - `admin/` - Admin CRUD pages for users, artists, albums, music
  - `[id].vue` - Dynamic route patterns
- `app/components/` - Vue components
- `app/composables/` - Reusable composition functions
  - `useMediaSession.ts` - Media session API integration
  - `useDominantColor.ts` - Image color extraction
- `app/stores/` - Pinia state management
  - `auth.ts` - Authentication state and JWT token management
  - `player.ts` - Music player state
- `app/middleware/` - Route middleware
  - `auth.global.ts` - Global authentication middleware
  - `admin.ts` - Admin role verification
- `app/layouts/` - Layout components
- `app/utils/` - Utility functions
- `app/types/` - TypeScript type definitions

### Important Files
- `nuxt.config.ts` - Nuxt configuration (SSR disabled, PWA enabled)
- `docker-compose.yml` - Production Docker setup
- `docker-compose.dev.yml` - Development overrides with hot reload
- `.env` - Environment variables (DATABASE_URL, CORS, JWT settings)

## Common Development Workflows

### Adding a New Entity
```bash
# 1. Create entity
docker exec -it api php bin/console make:entity EntityName

# 2. Generate migration
docker exec -it api php bin/console make:migration

# 3. Run migration
docker exec -it api php bin/console doctrine:migrations:migrate
```

### Creating a New Admin CRUD Interface
1. Backend: Create controller in `api/src/Controller/Admin/`
2. Frontend: Create pages in `front/app/pages/admin/resourcename/`
   - `index.vue` - List view
   - `add.vue` - Create form
   - `[id].vue` - Edit form

### Handling Audio Uploads
The `AudioUploader` service supports two methods:
- `uploadAndConvert(UploadedFile $file)` - Convert uploaded files to Opus
- `downloadFromYouTube(string $url)` - Download from YouTube and convert to Opus

Both methods ensure consistent 64kbps Opus output stored in `/public/uploads/music/`.

## Environment Configuration

### Required Environment Variables
- `APP_SECRET` - Symfony application secret (64 char hex)
- `DATABASE_URL` - MariaDB connection string
- `JWT_PASSPHRASE` - JWT keypair passphrase (64 char hex)
- `CORS_ALLOW_ORIGIN` - Frontend URL for CORS
- `DEFAULT_URI` - Backend public URL
- `NUXT_PUBLIC_API_BASE` - API base URL for frontend

### Ports
- Frontend: 3000 (configurable via `NUXT_PORT`)
- Nginx (API): 8000 (configurable via `NGINX_PORT`)
- Database: 3306 (configurable via `DB_PORT`)

## Docker Services

- `database` - MariaDB 10.11 with health checks
- `api` - PHP-FPM running Symfony, includes ffmpeg and yt-dlp
- `nginx` - Serves API via FastCGI, serves uploaded files
- `front` - Node.js running Nuxt in production or dev mode

## Authentication Flow

1. User registers via `/api/register`
2. User logs in via `/api/login_check` → receives JWT + refresh token
3. Frontend stores tokens in cookies (`token`, `refresh_token`)
4. Auth store (`app/stores/auth.ts`) manages authentication state
5. Global middleware (`auth.global.ts`) protects routes
6. Admin middleware checks for admin role on admin pages
7. Refresh tokens handled automatically by Gesdinet bundle

## Notes

- Frontend runs in SPA mode (SSR disabled)
- PWA enabled with service worker for offline support
- Audio files use shared Docker volume `uploads_data` between api and nginx
- Development mode mounts local directories for hot reload
- JWT keys auto-generated on first run via entrypoint.sh
